# Signal Desk 可靠性加固设计

## 目标

在不改变现有公开页面、后台路由和内容模型的前提下，修复审计中会影响公网稳定性和数据一致性的高优先级问题。首阶段覆盖请求边界、SQLite 并发、数据库初始化、图库文件一致性、服务端输入校验、响应安全头、会话生命周期和 logout CSRF。

## 方案

### 请求边界

所有 URL 编码表单和 multipart 请求都必须使用非负整数 `Content-Length`，超过对应上限返回 413，格式非法或负值返回 400。请求解析不会进入 `read(-1)`。

### SQLite 与迁移

`db()` 为每个连接设置显式 busy timeout，并启用 WAL。初始化创建 `schema_migrations` 表，首次数据库初始化写入当前版本。后续迁移按版本顺序执行，已有旧数据库先补齐结构再继续启动。迁移失败直接抛出，避免服务在半升级状态运行。

### Seed

示例数据只在数据库首次初始化时写入。生产数据库允许保持空内容表，后续请求不会重新创建示例内容。管理员记录仍保持现有首次创建行为。

### 图库一致性

上传先写入同目录临时文件，数据库提交成功后再原子改名。数据库提交失败会删除临时文件和已写入文件。删除先记录待删除文件，提交成功后删除文件，删除失败保留可重试状态并避免公开记录指向不存在的文件。

### 输入与安全

后台内容保存增加服务端必填、长度、标签和 URL 边界校验。HTML、静态文件和媒体响应增加 `X-Content-Type-Options`、`Content-Security-Policy` 和 `Referrer-Policy`。会话记录增加创建和最后访问时间并应用固定 TTL。logout 使用现有 CSRF token 校验。

## 错误语义

- 请求体长度格式错误返回 400
- 请求体超限返回 413
- SQLite 短暂锁竞争在有限等待后返回 503，并记录结构化错误上下文
- 已知唯一键冲突返回 409，其他完整性错误记录根因并返回通用 409
- 上传中途失败不留下已提交的数据库记录或无主文件

## 兼容性

现有路由、表单字段、HTML 结构和数据库内容保持兼容。迁移只追加表、索引和缺失列，不删除现有数据。测试数据库每次从空目录初始化，生产 volume 通过迁移版本逐步升级。

## 测试策略

先为每个修复写能复现现状问题的失败测试，再实现最小修复。覆盖负 Content-Length、迁移旧 schema、seed 空表、SQLite 锁、图库提交失败、字段边界、响应头、会话过期和 logout CSRF。完成后运行全部 unittest、Python 编译检查、Compose 配置检查和 git diff 检查。
