# 文章留言功能 PRD / 详细设计

## 1. 背景与目标

博客公开到公网后，访客可以直接给文章留下建议。留言提交后立即显示，站长可以在后台编辑留言、回复、隐藏或删除。

## 2. 用户与权限

| 角色 | 能力 |
|---|---|
| 访客 | 在已发布文章下提交留言，查看当前文章的可见留言和站长回复 |
| 管理员 | 查看全部留言，编辑内容，填写回复，切换可见性，删除留言 |

访客无需登录。IP 只记录并展示在后台，不出现在公开页面。

## 3. 核心流程

1. 访客打开 `/blog/<slug>`，在正文末尾看到留言区。
2. 访客填写留言并提交；服务端校验文章已发布、内容非空且不超过 2000 字。
3. 服务端记录文章 ID、内容、真实连接 IP、创建时间和可见状态，默认可见，返回文章页。
4. 文章页按创建时间倒序显示可见留言；有回复时显示站长回复。
5. 管理员在 `/admin/comments` 查看、编辑、回复、隐藏/恢复和删除留言。

## 4. 数据模型

新增 `comments` 表：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER | 主键 |
| post_id | INTEGER | 关联文章，级联关系由应用保证 |
| content | TEXT | 访客留言，最多 2000 字 |
| ip_address | TEXT | 服务端读取的 `client_address[0]` |
| reply | TEXT | 管理员回复，最多 2000 字，可为空 |
| visible | INTEGER | 1 显示，0 隐藏，默认 1 |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 最后更新时间 |

## 5. 接口与页面

- `POST /blog/<slug>/comments`：公开提交，URL encoded 表单；成功后 303 回到文章页，失败返回 400。
- `GET /admin/comments`：管理员留言列表，按最新时间倒序，显示文章、内容、IP、时间、状态。
- `POST /admin/comments/save`：管理员编辑内容、回复和可见性，使用现有会话和 CSRF。
- `POST /admin/comments/delete`：管理员删除留言，使用现有会话和 CSRF。

文章页留言表单包含一个隐藏 honeypot 字段；该字段有值时静默拒绝提交。公开接口按 IP 限制短时间内的提交频率，避免低成本刷屏。

## 6. 安全与边界

- 内容只按纯文本保存和 HTML 转义，不解析访客 Markdown 或 HTML。
- 留言最大 2000 字；请求继续受现有表单大小限制。
- 只接受已发布文章的留言，草稿/不存在文章返回 404。
- IP 不信任访客传入的 `X-Forwarded-For`。
- 隐藏留言不在公开页面输出，但后台仍可编辑和恢复。

## 7. 验收标准

1. 已发布文章显示留言区，未发布/不存在文章不能提交。
2. 合法留言立即出现在文章页，显示内容、创建时间和管理员回复（如有）。
3. 后台可编辑内容、填写回复、切换可见性和删除留言。
4. 后台列表显示文章标题、留言时间和 IP。
5. 空内容、超长内容、honeypot、频率限制和无效 CSRF 都被拒绝。
6. 留言内容中的 HTML/脚本不会执行。
